## 2026-09-28-vec0列类型与where过滤能力核对

- updated_at: 2026-09-28
- path: `docs/agent_notes/2026-09-28-vec0列类型与where过滤能力核对.md`
- 触发规则：当涉及 sqlite-vec 的列类型、KNN 的 where 过滤能力，或需要判断「库能力边界 vs 模块取舍」时阅读
- 内容摘要：核对 vec0 实际有 5 类列（向量 / 主键 / metadata / partition key / 辅助列，另有隐藏列 distance、k），且 metadata 列在 KNN 的 where 里支持等值、范围、IN、OR；本模块只实现等值、只用 3~4 类列。核心结论：等值限制是**模块接口的取舍**、不是库的限制，「普通列只能取等值」的说法是错的。

## 2026-09-28-砍功能前必须与用户对齐

- updated_at: 2026-09-28
- path: `docs/agent_notes/2026-09-28-砍功能前必须与用户对齐.md`
- 触发规则：在对外可见的功能 / 接口上准备「不做」「砍掉」「只支持 X」之前必读；用户提出「某个功能怎么没了 / 只能这样吗」时必读
- 内容摘要：记录一次严重错误用例——agent 在 `search` 的 `where` 上未告知用户就按「如无必要勿增实体」砍掉范围 / IN / OR 过滤，并把「模块取舍」表述成「库限制」，导致用户在检索时失去范围筛选能力。确立规则：用「勿增实体」的前提是**已与用户沟通一致、了解需要实现的基本功能**；若某设计会影响用户没想到的重大功能，agent 有义务**在砍之前告知**并交由用户在功能层面取舍。
