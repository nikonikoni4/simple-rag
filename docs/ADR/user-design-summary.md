## 决策偏好总结

- **先给直觉方案，再接受实证修正**。用户不排斥推翻自己的初始选择，但需要看到具体的实测证据而非一般性论证。
- **论证偏好「消掉对手理由」**：倾向于证明备选方案的独占优势不存在，而不是罗列所选方案的好处。
- **理由陈述压缩**：口头给的理由往往短、依赖记忆、可能不精确。需要主动复核。
- **隐含前提在追问下可补全**：用户能回答「你指的是哪一层」这类具体化问题，但不会主动展开。
- **先定立场再定接口**：面对接口形状选择时，先点破并确认背后的架构前提（如"vec 必须存在"），由立场推出接口形状，并要求明确前提失效时的切换路径。
- **对"改现状"有惰性，细节可委托但要知情**：涉及既有契约（如分数方向）时倾向「现在是什么就是什么」；AI 显式标注「我直接定了，有异议选 Other」的技术细节会默认接受——委托的前提是被明确告知，不是被瞒着。
- **会逐条核查 AI 结论的口径**：不接受未标注口径的对比数字。2026-10-01 连续三次质疑都指向 AI 表述的口径而非数据（「辅助表查询会进行 2 次查询，我不知道你算没算」「你前面的结论辅助表更快是错误的」「我在这里质疑你说辅助表是能力上限」）—— 数字本身没错，错的是把它当成了方案级结论。
- **自己构建方案空间**：面对选型问题倾向自己拆维度（2026-10-01 自己拆出三种存储方案并自推前提链条「必返回 path → 必然 2 次搜索 → 方案 2 不如方案 1」），AI 的职责是**补实测数据与核对口径**，不是给选项。
- **主动把前提送检，并严格圈定范围**：2026-10-02 他给出的两条理由自带「先去判断原因2是否成立」的送检要求 —— 自己的判断他会要求实测检验，与引用他人建议时的照单全收形成对照。同一轮里他两次收回 AI 的扩写：纠偏跑题（「我并没有说是速度，我说的是内存啊」）、砍掉 AI 自行加入的能力集与命名（「不需要写命名，只写我上面说的内容」）。**给该用户写文档时只写他明确说过的内容；要多写之前先问。**

## 给后续 agent 的参考

- **可以参考的判断原则**：做架构决策时，先问「对手方案的理由在当前约束下是否还成立」；用户对这个思路接受度高，也乐于被证据说服。
- **必须重新确认的前提**：用户口头给出的理由（尤其是压缩成一句话的），落成 ADR 前必须逐条与实测证据核对，措辞偏差要显式指出。
- **不建议直接沿用的做法**：不要因为用户说「都要」（如四层独立性全选）就认为四层都已被论证。未论证的部分要标出来，并在相关下游决策（如备份方案）时重新确认。
- **给方案对比时先摆隐含前提**：呈现二选一时，显式列出「前提 → 方案 → 前提失效时切到哪」的映射。用户会主动点破决策背后的隐含前提，先确认立场再定接口的路径更契合其判断方式。
- **「保持现状」类回答要展开校验**：用户答「现在实现的就是什么」时，可能隐含未验证的事实假设（本次「分数恒为负」就被 rank_bm25 退化语料实测推翻，契约最终只落在"方向"上）。把"现状"的精确性质写进契约并实测。用户引用的外部建议（别的 AI 的说法，如「pickle 可以 save 和 load」）不带论证，版本绑定、安全性等代价的复核义务在当前 agent。
- **汇报实测数据必须主动标注口径**：每项对比要说明它是「纯定位 / 完整链路 / 方案级」中的哪一种。2026-10-01 把纯定位的「4700 倍」放在结论显眼处，被用户逐条核对出来并要求更正 —— 该用户对数字口径敏感，主动标注比被动纠正成本低。
- **优先补数据，不要急着给选项**：该用户会自己搭方案空间，AI 的价值在于把每个方案的关键未知量测出来（如本次的探针 24/25），而不是替他选。
